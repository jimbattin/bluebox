# Lexicon 224XL DSP microinstruction format

Sources:
- Lexicon **Model 224X** service manual: https://therackofages.com/Lexicon/224x%20digital%20reverborator/Lexicon-224X-Service-Manual.pdf. It is a scan with no text layer; the page numbers below are 1-based PDF pages. The 224XL is a 224X with the LARC head (see CLAUDE.md), so the 224X T&C, ARU and DMEM cards apply.
  - pp.17–23: theory of operation §3.5–3.8 (manual pages 3-8 to 3-14).
  - p.110 / p.111: T&C schematic 060-02475 rev 1, sheets 1 / 2. Sheet 2 holds the WCS, the microinstruction register and the decoders.
  - p.90: ARU schematic 060-01318.
- The 1980 Model 224 manual (`224_service_manual.pdf`), for the I/O port table only (see [memory_map.md](memory_map.md) §6).
- The 20 microcode records in the ROM set (see [rom_map.md](rom_map.md) §4).

Reference designators (Uxx) below are on the 224X T&C unless stated otherwise.

To print every record decoded with this layout, run:

```
uv run tools/ucode_dump.py [microcode id ...]
```

The ids are hex (e.g. `08` for CHAMBER). With no ids, every record is printed.

`emu/` holds a C++ emulator, `lex224emu`, that runs this layout end to end. It boots the v8.2 ROMs on an emulated 8080 SBC, forces a factory program at the program-select call (NVS1 8163), and runs the loaded WCS image on a WAV file. Build and usage instructions are in [emu/README.md](../emu/README.md).

The 8080 and the DSP share one 30.72 MHz timeline: an 8080 T-state is 15 ticks (2.048 MHz) and a DSP step is 9 ticks. On the hardware the SBC has its own 18.432 MHz crystal (SBC 80/10 hardware reference manual §3.2.1), so the fixed ratio and phase between the two are the emulator's. Every off-board (Multibus) machine cycle of the 8080 costs it one wait state (`Machine::kWaitStates`): NVS ROM and RAM, WCS and DSP ports 00–09. On-board SBC ROM, RAM and I/O cost none (§3.2.1). The count is `[INFERENCE]`: an off-board write takes at least one (Fig. 3-4), a read none only if XACK/ answers within 191 ns of the command (Table 7-2), and the NVS card's XACK/ timing is `[unknown]`. While the DSP runs, an SBC access to the WCS stalls until the next `PROT` step. The firmware rewrites WCS coefficients during playback (interpolated delay modulation, NVS3 AE8C–AE8F); the stalls take only about 4% of the 8080's time then, so the update rate follows the 8080's own speed. Without the wait states it was 16% higher.

The ARU arithmetic and the FPC conversion are traced bit by bit in [aru_fpc.md](aru_fpc.md); the emulator's multiply-accumulate reproduces every ARU self-test vector in the ROM. One numeric choice here is still `[INFERENCE]` from the data:
- ADC reads alternate L, R within a sample.

DMEM is modelled as 64 Kwords, which V8.2 requires. Stock units have 32 K words; see [memory_map.md](memory_map.md) §5.

## 1. Hardware summary

From the 224X manual, pp.17–23:
- **Clock.** The master clock MC runs at 30.72 MHz. Divided by 9, it gives a 293 ns system cycle, split into nine time slots MS0–MS8. The slots are grouped into three ARU states, AS0, AS1 and AS2.
- **Writable control store (WCS).** Four 128 × 8 static RAMs (U2, U15, U29, U43) form a 32-bit microinstruction word. The WCS is addressed by the program counter U1/U14 (74163s) and appears at 4000–41FF in the 8080 address space.
  - The SBC can access the WCS with the DSP halted (`HALT/`).
  - It can also access it while the DSP runs, but only in steps whose protect bit allows it. The displaced microinstruction must be a no-op. A flip-flop pairs the SBC accesses within one sample time.
- **No-op word.** The upper 16 bits are cleared during an SBC access, and "all zeros correspond to a no-operation".
- **ARU.** The ARU has:
  - a 4 × 16-bit register file with independent write (WA) and read (RA) addresses;
  - a 16 × 6-bit multiplier;
  - a 20-bit accumulator that saturates (to 19 bits: the multiplicand carries two sign bits; see [aru_fpc.md](aru_fpc.md) §2);
  - a 16-bit result register.

  A multiply-accumulate happens every cycle. The register file is written every cycle (`DAB WSTB/`), so address 3 is used as a pass-through.
- **Pipelining.** A multiply-accumulate result is not ready until the end of AS0 of the *next* cycle. At that moment `XFER` loads the result register, and `ZERO` clears the accumulator. In step terms (fixed by the ROM self-tests, [aru_fpc.md](aru_fpc.md) §2): `XFER` in step *n* captures the products through step *n* − 1, and `ZERO` in step *n* keeps step *n*'s own product.
- **DMEM.** Absolute address = current-position counter (16-bit, U51/U65) − offset. The DMEM adds the complemented offset `OFST/` with the carry-in high. It holds one bank of 64 K or two banks of 16 K dynamic RAMs.
- **Program length.** The manual says: "A 100-step control program is allowed, giving a sampling rate of 34.13 kHz. Thus the counter is normally reset at count 99 by a RESET signal that is generated by the WCS itself." §5 compares this with the ROM.

## 2. From the 8080's view to the microinstruction

The Multibus address and data lines are active-low. The T&C wires `ADRx/` and `DATAx/` straight to the WCS (sheet 2), which introduces three inversions:

1. **Data.** The data lines drive the RAMs through transceivers U3, U16, U30 and U44, so each microinstruction bit is the complement of the bit the 8080 wrote. As a result, an FF-filled step is an all-zero microinstruction, which the manual defines as the no-op. Everything below is stated in **8080 terms**: the byte values as they appear in the ROM and at 4000–41FF.
2. **Byte lanes.** U46 (74LS155) decodes `ADR0/` and `ADR1/`. Byte +0 selects U43 (MI0–7), +1 selects U29 (MI8–15), +2 selects U15 (MI16–23) and +3 selects U2 (MI24–31). So each step is a little-endian 32-bit word: bit *k* of the word is microinstruction bit MI*k*.
3. **Step order.** U42/U28 multiplex `ADR2/`–`ADR8/` with the program counter. The 8080's step *n* (4000h + 4n) is therefore WCS address 127 − *n*. Since the counter starts at 0, execution begins at step 127 and runs downward. `pc` in the dump is the WCS address.

Evidence for (3):
- Every record's code sits in steps ~20–127, with FF or data below.
- Every record reads the ADC at step 127 (pc 0).
- Every record's single RESET is followed, in this order, by a no-op delay slot (§4).

## 3. Field layout

Bits are bits of the little-endian 8080 word. "Active 0" means the function is selected when the bit is 0 (the microinstruction bit is 1).

|Bits|Byte|Signal (sheet 2)|Meaning|
|---|---|---|---|
|0–15|+0, +1|`OFST0/`–`OFST15/` (U45, U31 → DMEM)|Memory ops: offset in samples. Address = current position − offset. I/O ops: the sub-operation bits in the next table|
|16–17|+2 b0–1|U47a (LS139) A = MI16, B = MI17|(b17, b16): 11 = no bus op, 10 = I/O (`OPER/`), 01 = memory write (`MEMW/`), 00 = memory read (`MEMR/`). `MEMAC` = MI17, i.e. b17 = 0 on memory cycles|
|18–19|+2 b2–3|`WA0/`, `WA1/` (U17)|Register written this cycle = b18 + 2·b19|
|20–21|+2 b4–5|`RA0/`, `RA1/` (via latch U19)|Register read by the multiplier = b20 + 2·b21|
|22|+2 b6|`PROT` (U18)|1 = SBC access slot `[INFERENCE: polarity]`|
|23|+2 b7|`CSIGN/` (U19, then JK U20 at AS0)|Coefficient sign: 1 = positive (ARU self-test vectors, [aru_fpc.md](aru_fpc.md) §3)|
|24|+3 b0|`XFER` (U19)|Active 0: load the result register from the accumulator|
|25|+3 b1|`ZERO/` (U19 → U48D, gated with a timing signal)|Active 0: clear the accumulator|
|26–31|+3 b2–7|`C0/`–`C5/` (U4, U5 → shift registers U11, U10 → `M0/`, `M1/`)|Coefficient magnitude *m* = NOT bits 26–31, i.e. `(~byte3 >> 2) & 3Fh`. Value = *m*/32, range 0–1.96875|

The sign and scale are established from the ROM data (§5) and the ARU self-test ([aru_fpc.md](aru_fpc.md)). U11 serialises C0/C2/C4 onto `M0/`, and U10 serialises C1/C3/C5 onto `M1/`; the ARU takes the pairs (C5, C4), (C3, C2), (C1, C0) in AS0, AS1, AS2.

### I/O sub-operations (op = 10)

In an I/O step the offset field is decoded instead of going to the DMEM.

|Bits|Signal|Meaning|
|---|---|---|
|13, 12|U47b A = MI12, B = MI13, enabled by `OPER` and a timing strobe|(b13, b12): 11 = none; 10 = `RD RREG` (result register → data bus); 01 = `RD XREG` (the X register the 8080 writes with OUT 06h/07h → data bus); 00 = `RD AD` (ADC via FPC → data bus). U47b Y0 is not connected|
|11, 10, 9, 8|`SDAA`, `SDAB`, `SDAC`, `SDAD` (U32 LS08)|Active 0: DAC output channel A, B, C, D|
|7|`WR DA/` (U49C)|Active 0: write the data bus to the DAC|
|6|`WR XREG/` (U49A)|Active 0: latch the data bus into the X register the 8080 reads via IN 06h/07h. It is a separate register from the one `RD XREG` reads ([aru_fpc.md](aru_fpc.md) §3)|
|5|`TEST` (U49B)|Active 0: pulse on the TEST point only|
|4|`DP` (U34A, latched in U19, used by sheet-1 timing)|Active 0. Purpose `[unknown]`; never set in an executed step of any record|
|3|`RESET` (U34B → U25 → `RESET/`)|Active 0: clears the program counter (U1/U14 CLR) and resynchronises the FPC|
|0–2, 14–15|—|Unused; 1 in every executed I/O step|

A memory-write step also asserts `RD RREG`: U48A ORs `MEMW/` with U47b Y1. So a memory write stores the result register.

### What drives the data bus each cycle

- Memory read: DMEM output.
- Memory write: the result register (and the DMEM stores it).
- I/O step: the selected read source.
- Otherwise: nothing.

The register file latches the bus into register WA every cycle, so steps without a source use WA = 3.

## 4. Execution order and loop length

- The program counter steps through WCS addresses 0, 1, 2, …
- A RESET at pc *p* clears the counter. The step at *p* + 1 still executes, as a pipeline delay slot. The sample loop is therefore *p* + 2 steps.
- In every record:
  - there is exactly one RESET in the executed range;
  - the delay slot after it is a no-op;
  - nothing in the record executes after the delay slot.
- Steps below the loop are never executed. Some records keep non-code bytes there (e.g. record 01, steps 0–4).

The loader writes the 3E4E–3F4D image, not the record, into bytes +0/+1, so the record's own +0/+1 bytes are not what runs. They match each step's op type (§5) `[INFERENCE: templates for the image]`, and they are what `tools/ucode_dump.py` decodes.

Loop lengths implied by the record templates:

|Loop (steps)|Records|
|---|---|
|100|02, 08, 21, 0C, 14, 24|
|102|10, 06|
|104|0A, 12, 42|
|105|01, 20, 40, 22|
|107|05|
|108|81, 80, 41|
|109|11|

Only 6 of 20 match the manual's 100 steps. However, bytes +0/+1 (and with them the RESET bit) are replaced at load time by the image built at 3E4E–3F4D (see [memory_map.md](memory_map.md) §4). While that image is being rebuilt, the loader (NVS3 AA5A–AA63) temporarily forces two low words:
- step 29 (pc 98) = EA77h: `RD RREG`, `WR DA` B+D, `RESET`;
- step 78 (pc 49) = E57Fh: `RD RREG`, `WR DA` A+C.

That is a 100-step loop, but only while the image is being rebuilt. The emulator executes the firmware's own image builder, and after loading, every one of the 22 factory programs runs its record template's loop length (`lex224emu` status line and `emu/README.md` "Presets"; the Daisy pedal logs the same lengths on the device). The builder's code is still not decoded step by step.

## 5. Evidence from the ROM records

The loop, ADC/DAC, access-slot and allpass figures are printed in the per-record summaries of `uv run tools/ucode_dump.py`. The low-word and sign-bit counts were tallied over the same decode.

- **Low words match the op type** (templates, all 128 steps of all 20 records). I/O steps hold I/O patterns: EFFFh (`RD RREG`) 87×, CFFFh (`RD AD`) 25×, CFBFh 15×, and E77F/E67F/ED7F/EE7F/EB7F/E97Fh (`RD RREG` + `WR DA` to channel sets). Memory steps hold small numbers (offsets). No-op steps hold FFFFh (527 of 570).
- **No stray I/O bits.** No executed I/O step sets a bit outside the I/O table, and none sets `DP` or `TEST`.
- **ADC and DAC positions.** Every record reads the ADC at pc 0 and again at pc 48–54. Every record writes two to four DAC channels.
- **Coefficient sign and scale.** Allpass sections appear as the run `MR +g`, `MW k`, `MW −g`, where the two g coefficients have equal magnitude and opposite bit 23. There are 138 such runs, and in 135 of them k = round(32·(1 − g²)) ±1 with g = *m*/32.

  For example, CHAMBER uses g = 0.5 → k = 0.75, g = 0.4375 → k = 0.8125, and g = 0.25 → k = 0.9375. The fit fails for *m*/64.
- **Sign polarity.** Bit 23 = 1 on 1271 of the 1573 coefficient-bearing executed steps. Treating 1 as positive makes reverb gains and decays positive.
- **Access slots.** Every record has exactly two steps with bit 22 = 1. In 17 of 20, one of them sits directly before RESET. This matches the manual's pairing of two SBC accesses per sample. The dump marks them `SLOT`.

## 6. Open questions

- **`PROT` polarity.** Inferred from the data, not traced through the T&C gates. (`CSIGN/`'s polarity is fixed by the ARU self-test.)
- **`MW` with `XFER`.** Whether a memory write in an `XFER` step stores the old or the new result: see [aru_fpc.md](aru_fpc.md) §6.
- **`DP`.** Its effect on the sheet-1 state machine is `[unknown]`.
- **`SDAA`–`SDAD` gating.** The common input of U32 is `[unknown]`; it is probably `OPER` or `WR DA`.
- **Record bytes 00–A9.** The header format is `[unknown]`, and so are the non-code bytes in unexecuted steps.
- **Wait states.** The XACK/ timing of the NVS card and the DSP cards, which sets `Machine::kWaitStates` (1 assumed). The firmware's live rates scale with it: a second wait state would lower them by another 13%.
